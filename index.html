01 Purpose

Software that answers to you.

SoraPlatform is an umbrella for open-source, independent products built for the mass tech community — not for a boardroom. Big tech keeps forcing AI features and clunky products down users' throats. SoraPlatform stands opposed to that.

The belief is simple: software should be efficient, individually controlled, and broadly accessible. No telemetry. No mandatory cloud. No bloat.

“The true value of software lies in its efficiency, individual control and broadability.” — SoraPlatform roadmap

Efficiency by default

Small, readable systems. A standard-library agent core, explicit layers, and prompts that stay lean instead of ballooning with every feature.

Individual control

Local-first by design. You choose the provider, the machine, and the connection — including whether the network is involved at all.

Broad by design

Open source, framework-agnostic skills, and a roadmap that reaches beyond the desktop into the tools people use every day.

03 SoraAgent

The engine, in detail.

The central engine of SoraPlatform. A model-agnostic Python harness: the model/tool loop is deliberately small; approval, validation, evaluation, memory, and identity sit in explicit layers around it.

Human approval gate

Tools marked needs_approval never execute without a human saying yes.

Quality gate

Every finished trajectory is graded by a deterministic structural evaluator. The grade is advisory and cannot affect execution.

Lazy tool discovery

Only find_tools and memory_recall are visible at the start; the rest load on demand, keeping prompts small and tool lists bounded.

Local memory & identity

File-backed USER.md and SOUL.md, plus optional CortexDB recall with a memory firewall.

The shell: one protocol, three connection modes, no duplicated agent state.

One protocol, three connections

Local loopback, a supervised SSH tunnel that reuses your keys, or opt-in direct IP with TLS and a device token.

Chat that streams and asks

Streamed replies, tool and file-edit chips, human approvals, stop/interrupt, and draft queueing while a turn is running.

Attachments and voice notes

Paperclip, drag & drop, paste, or record. Images, audio, video, and files all upload through the same media.upload frame.

Agent state, not a duplicate

Sessions, calendar, and memories read SoraAgent’s own store. Settings manages profiles, pairing, the local bridge, and updates.

Connection modes

Local loopback, supervised SSH tunnel, and opt-in direct IP. Pairing codes authorize devices; passwords are never stored.

Built with

Tauri v2 with a Rust shell for transport, tunnels, and reconnect logic; a vanilla TypeScript UI; and a Python bridge into SoraAgent.

Status

v0.1.0, built against the frozen v1 protocol. Tagged builds produce signed updater artifacts; the first public release is being prepared.
